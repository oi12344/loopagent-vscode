## 功能 1: exploreCode Spool 机制

### 问题
- **边截断是盲目的**：按 BFS 遍历顺序截断，可能丢失关键调用关系
- **模型无法判断缺失**：看不到被截断的边，无法判断是否需要补读

### 解决方案
**预览 + 完整备份（spool）混合策略**

#### 1. 边智能排序
```typescript
// 排序优先级：
// 1. 入口节点相关的边（查询主体）
// 2. calls > extends/implements > imports/references
rankEdges(edges, entryNodeIds)
```

#### 2. Spool 文件机制
```
.loopagent/runs/{conversationId}/
  └── explore-{runId}-{timestamp}.json
```

包含完整图数据：
```json
{
  "entryNodes": [...],
  "relatedNodes": [...],
  "edges": [...],  // 所有 156 条边
  "totalEdges": 156,
  "previewEdges": 28
}
```

#### 3. 返回格式改进
```markdown
⚠️ **完整调用图已保存**: .loopagent/runs/abc123/explore-xyz.json
- 预览显示: 28 条边（按相关性排序）
- 完整图包含: 156 条边

使用 readFile() 获取完整图的 JSON 数据
```

## 功能 2: 缓存管理改进

### 问题
- **缓存是模块级全局变量**，跨会话泄漏
- **工作区改动后缓存不失效**，模型看到旧代码

### 解决方案

#### 1. 实例级缓存隔离
**修改前（模块级）：**
```typescript
const queryCache = new Map<string, { ... }>();  // 模块顶层
```

**修改后（实例级）：**
```typescript
export function createExploreCodeTool(...) {
  const queryCache = new Map<string, { ... }>();  // 实例内部
  return {
    invoke() { ... },
    clearCache() {
      queryCache.clear();
    }
  };
}
```

#### 2. 工作区改动后自动清理
```typescript
if (WORKSPACE_MUTATING_TOOLS.has(request.name)) {
  succeededCalls.clear();
  for (const tool of tools) {
    tool.clearCache?.();  // 清理所有工具缓存
  }
}
```

### 效果
- ✅ 缓存按工具实例隔离，不跨会话泄漏
- ✅ applyEdit 后 exploreCode 返回最新结果
- ✅ 避免"模型看旧代码 → 误判 → 重复调用拦截"死循环

### 性能开销
- **清理耗时**：~0.1ms（可忽略）
- **触发频率**：仅在 applyEdit/runCommand 成功后

## 功能 3: 对话历史压缩

### 问题
- **messages 数组只增不减**，无上下文溢出处理
- **长对话会导致 API 失败**（超过模型上下文限制）

### 解决方案

#### 1. 滑动窗口压缩
```typescript
export function compressConversationHistory(
  messages: ReactAgentMessage[],
  options: { maxMessages: number; keepRecentMessages: number }
): ReactAgentMessage[]
```

**保留规则：**
- 系统提示（第一条）- 永久保留
- 摘要消息（压缩中间部分）- 统计型摘要
- 最近消息（最后 20 条）- 完整保留

**压缩示例：**
```
压缩前：60 条消息
压缩后：[系统提示] + [摘要] + [最近 20 条] = 22 条消息
节省：66% tokens
```

#### 2. 触发条件
```typescript
const estimatedTokens = estimateTokenCount(messages);
if (messages.length > 50 || estimatedTokens > 80_000) {
  const compressed = compressConversationHistory(messages, {
    maxMessages: 50,
    keepRecentMessages: 20,
  });
}
```

#### 3. Token 估算
```typescript
// 粗略估计：4 个字符 ≈ 1 个 token
function estimateTokenCount(messages: ReactAgentMessage[]): number {
  let totalChars = 0;
  for (const msg of messages) {
    totalChars += msg.content.length;
    if (msg.reasoningContent) totalChars += msg.reasoningContent.length;
    if (msg.toolCalls) totalChars += JSON.stringify(msg.toolCalls).length;
  }
  return Math.ceil(totalChars / 4);
}
```

- **压缩耗时**：~1-2ms（60 条 → 22 条）
- **节省 token**：66%（中间 40 条压缩为摘要）
- **额外延迟**：0（纯计算，无 API 调用）

## 核心洞察

### 1. 分层返回 > 二选一
不是"全要预览"或"全要 spool"，而是：
- **立即可见的智能预览**（按相关性排序的 top-N）
- **按需加载的完整备份**（所有数据的 JSON）

在工程上平衡了**延迟、完整性和资源开销**。

### 2. 实例隔离 > 全局共享
缓存应该与工具实例生命周期绑定，而不是模块级全局变量。

### 3. 固定窗口 > 动态计算
对话压缩选择固定窗口而非动态计算：
- 零额外延迟（无 API 调用）
- 零额外成本（纯计算）
- 可预测行为（工程友好）

### 4. 粗略估算 > 精确计算
Token 估算用粗略公式（4 chars/token）而非 tokenizer：
- 目的是**预警**而非精确计数
- 宁可早压缩也不要爆上下文
