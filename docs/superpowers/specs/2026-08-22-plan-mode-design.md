# 计划模式设计

## 目标

在 LoopAgent 输入框工具栏提供显式的“计划 / 执行”模式。计划模式为一次请求建立只读边界，要求模型输出可执行计划；执行模式保持现有行为。

## 范围

- 在 composer 工具栏最左侧添加“计划 / 执行”分段控件，默认执行模式。
- 新建对话和继续对话消息携带本次请求的 `mode`。
- 扩展端在计划模式下只提供现有只读工具，且加入计划输出约束。
- 运行中禁用模式切换，避免单次请求的模式漂移。

## 非目标

- 不强制创建 `planner` 子代理，不改变现有动态 DAG 调度。
- 不增加“确认计划后自动执行”、计划审批状态或独立计划存储。
- 不修改既有执行模式的工具集合、审批和编辑回退流程。

## 交互与协议

composer 工具栏顺序为：模式分段控件、模型控件、思考控件、发送/停止按钮。控件使用可访问的单选组语义；选中的模式高亮。计划模式运行时，按钮保持禁用直到本轮完成或停止。

`WebviewToHostMessage` 的 `startTask` 与 `continueConversation` 增加可选字段：

```ts
mode?: "plan" | "execute";
```

Webview 始终发送当前模式；Host 将缺失字段解释为 `"execute"`，保持已有调用方兼容。

## 运行边界

计划模式使用与当前主代理相同的对话和流式返回通道，但传入的工具列表仅保留只读工具。系统消息明确要求：先基于已知上下文和只读查询输出有序计划、涉及文件与验证命令；不得编辑文件、运行命令或声称已经执行。

该边界由 Host 的工具注册保证，而非仅依赖提示词。即使模型请求写入或命令工具，运行时也不会暴露这些工具。

## 失败处理

- 模式字段缺失：按执行模式处理。
- 模式字段不是已知值：按执行模式处理，不让无效 Webview 消息中断对话。
- 只读工具失败：沿用既有 Agent 错误和流式失败呈现；不退化为写入工具。
- 中止、会话切换与恢复：维持当前语义。既有中断 checkpoint 仅额外保存本次 `mode`，确保计划模式恢复后仍不暴露写入工具。

## 验证

- `test/App.test.tsx` 覆盖默认模式、切换、运行时禁用与两类消息 payload。
- Host 边界测试覆盖计划模式移除 `applyEdit`、`runCommand`，以及缺失/无效模式按执行处理。
- 运行受影响测试、全量 `npm test -- --run`、`npm run typecheck`、`npm run compile` 与 `git diff --check`。
