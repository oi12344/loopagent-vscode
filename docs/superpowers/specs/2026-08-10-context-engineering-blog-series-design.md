# LoopAgent 上下文工程知识博客系列设计

## 1. 目标

为 LoopAgent VS Code 扩展编写一套独立的中文知识博客系列，解释本系统如何收集、筛选、组装、更新和保护模型上下文。文章既要能沿着当前源码追踪真实调用链，也要通过具体场景帮助读者理解上下文工程的工程取舍。

系列与现有 `blog/` 下的代码搜索系列并列，不修改既有文章的编号和目录结构。新系列放在 `blog/context-engineering/`，由 `README.md` 提供总目录。

## 2. 范围与边界

### 包含

- `providerRegistry` 的 system prompt 装配流程。
- VS Code 运行时上下文：工作区、活动编辑器、选区、光标附近代码、标签、项目文件和诊断信息。
- 工作区代码智能、`browseSymbols`、`exploreCode` 与上下文预算。
- 对话历史的格式化、当前任务追加和跨轮语义保持。
- 项目记忆的检索、证据、generation、过期和 stale 状态。
- ReAct 工具结果如何作为增量证据进入推理循环。
- 索引或记忆不可用时的降级、截断、失败隔离和安全边界。
- 面向其他 Agent 系统的可迁移设计检查清单。

### 不包含

- 不把尚未接入生产调用链的示例模块写成现状。
- 不把设计文档中的未来计划写成已经实现的行为。
- 不新增运行时代码、测试代码或上下文协议。
- 不覆盖与上下文工程无直接关系的 UI、打包和部署主题。

## 3. 文章结构

系列共 8 篇：

1. `001-上下文工程不是拼Prompt.md`：一次请求中的上下文分层与装配线。
2. `002-第一现场运行时上下文.md`：VS Code 当前状态如何变成可消费的上下文。
3. `003-代码索引与信息密度.md`：用符号、语义索引和预算替代整仓库注入。
4. `004-对话历史与语义连续.md`：多轮任务中的历史格式化和上下文保持。
5. `005-项目记忆与可信边界.md`：有证据、可过期、可撤销的长期记忆。
6. `006-工具结果就是证据.md`：ReAct 循环中的上下文增量和停止条件。
7. `007-上下文失效时如何降级.md`：索引故障、截断、恶意内容和失败隔离。
8. `008-上下文工程检查清单.md`：相关性、时效性、证据性、可控性、可恢复性、可观测性。

每篇统一采用“具体场景 → 核心问题 → 源码调用链 → 最小示例 → 设计取舍 → 失败边界 → 可迁移原则”的结构。示例优先使用本仓库可解释的场景，例如活动编辑器定位、跨文件签名修改、三轮对话承接和 SQLite 不可用时的降级。

## 4. 事实准确性要求

文章中的实现事实必须关联当前源码、测试或设计文档路径。对于示例推演和方法论结论，使用明确的“示例”“推演”或“设计原则”标记。涉及生产行为时，优先沿 `providerRegistry.ts`、`contextPrompt.ts`、`codeRuntimeContext.ts`、`projectMemory.ts`、`reactAgentRunner.ts` 及其直接测试确认。

## 5. 交付与验证

- 新增 `blog/context-engineering/README.md` 和 8 篇正文，全部使用中文 UTF-8 Markdown。
- README 只负责导航、阅读顺序和系列定位，不重复正文细节。
- 完成后检查链接、标题层级、代码围栏、路径引用和明显的占位符。
- 使用 `git diff --check` 检查空白错误，并逐篇核对源码引用是否存在。

## 6. 后续事项

正文写作阶段若发现当前实现与设计文档存在差异，博客以当前生产调用链为准，并在文中明确差异，不顺带修改系统代码。
