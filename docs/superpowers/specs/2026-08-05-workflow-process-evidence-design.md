# 工作流计划过程证据与工具折叠

## 目标

让用户在助手的思考过程时间线中看到工作流计划生成与校验的可验证进度，并让每个工具调用的输入和输出可以分别折叠，保持时间线按发生顺序展示。

## 范围

- 工作流协调器在计划生成前、候选计划收到后、计划解析和结构校验完成后发送结构化过程事件。
- 过程事件只描述已发生的系统动作、节点数量、依赖校验结果和错误，不展示模型隐藏的原始思维链。
- WebView 将多条同类过程事件保留为独立时间线条目，不再用固定 ID 覆盖前一条。
- 工具时间线条目继续通过 `callId` 合并输入和输出；Input、Output 各自使用原生 `details` 折叠。

## 事件与状态

计划阶段至少包含以下可观察信息：

1. 开始生成计划。
2. 已收到候选计划，开始解析和校验。
3. 校验通过，显示节点数量以及依赖关系检查结果。
4. 解析或校验失败，显示可读错误并结束为失败状态。

事件沿用现有 `assistantThinking` 和 `workflowStateChanged` 消息，避免新增跨层协议；每个阶段使用不同的活动 ID，UI 按时间顺序追加。

## UI 行为

- “思考过程”时间线显示计划阶段条目、普通思考摘要和工具调用。
- 工具条目默认保持时间线可扫描；Input 和 Output 作为两个独立的折叠块，标题中标明字段和状态。
- 工具调用未完成时只显示已收到的字段；完成后补齐另一字段，不改变条目位置。
- 完成的运行默认收起整个思考过程；运行中、失败和中断时保持展开。
- 执行计划只展示节点任务和非工具节点证据，工具详情仍集中在思考过程时间线中。

## 验证

- WebView 单测验证：多个计划阶段事件按顺序保留；同一工具调用的 Input/Output 仍成对；两个字段均可通过 `details` 独立折叠。
- 协调器单测验证：计划生成、解析/校验成功和失败分别产生对应过程事件，非法计划不会执行。
- 运行 `npm.cmd run compile`、受影响 Vitest 测试及 `git diff --check`。
- 在现有单一 VS Code 调试窗口通过 CDP 发送一轮真实任务，确认时间线可见且工具字段可展开/收起。
