# 子代理固定角色模板设计

## 状态

- 日期：2026-07-24
- 状态：待用户评审
- 关联实现：[子代理工作流执行更正](./2026-07-24-subagent-workflow-execution-correction.md)

## 背景

当前子代理已经拥有独立 runner、消息历史、状态、超时和只读工具，但所有子代理共用同一套基础提示词与模型配置。任务文本决定子代理做什么，尚不能稳定约束它以何种角色完成任务。

## 目标

为每个子代理解析一个固定角色模板，使角色负责稳定的职责、提示词和工具边界，任务参数只描述本次要完成的工作。

主代理继续负责调度、依赖、并发、取消和权限控制；子代理只负责在独立上下文内执行任务并返回结果。

## 方案比较

### 方案一：固定角色模板，按任务创建无状态实例（采用）

每次创建子代理时选择预定义角色，并创建全新的执行上下文。角色不保存跨任务记忆。

优点：上下文隔离清晰、行为稳定、资源容易回收，符合当前工作流架构。

### 方案二：常驻角色智能体（暂不采用）

每个角色长期保留消息和记忆。它适合持续协作，但需要持久化、版本迁移、上下文压缩和生命周期管理，超出当前需求。

### 方案三：调用方动态传入提示词、模型和工具（不采用）

虽然灵活，但会让模型绕过既有工具白名单和权限边界，也会使行为难以测试和审计。

## 角色定义

第一阶段只提供三个只读角色：

| 角色 | 固定职责 | 允许工具 | 输出要求 |
| --- | --- | --- | --- |
| `explorer` | 定位源码、符号和调用链，收集事实证据 | `exploreCode`、可选 `readFile` | 结论、证据位置、未知项 |
| `reviewer` | 检查缺陷、回归风险和测试缺口 | `exploreCode`、可选 `readFile` | 按严重级别列出发现；无问题时明确说明 |
| `planner` | 基于现有实现拆解最小执行步骤和验证路径 | `exploreCode`、可选 `readFile` | 有序步骤、涉及文件、验证命令 |

角色模板由扩展内部维护：

```ts
type SubagentRoleId = "explorer" | "reviewer" | "planner";

type SubagentRoleProfile = {
  id: SubagentRoleId;
  systemPrompt: string;
  allowedTools: readonly string[];
};
```

创建参数不允许覆盖模型、提示词或工具白名单；这些配置只能由扩展内部的角色模板定义。

## 创建参数

主代理创建子代理时使用：

```ts
type CreateSubagentConfig = {
  task: string;
  role?: SubagentRoleId;
  dependsOn?: string[];
  toolHints?: string[];
  timeoutMs?: number;
};
```

`role` 省略时解析为 `explorer`，以兼容现有调用。未知角色在创建阶段直接拒绝。

`toolHints` 只能在角色工具白名单与父运行只读工具集合的交集中进一步缩小工具，不能扩大权限。

## 上下文边界

每次创建都生成新的子代理执行上下文，包含：

- 已解析的角色 ID 和固定 system prompt；
- 本次 `task`；
- 独立消息历史、状态、超时和取消信号；
- 经过角色白名单和父运行权限共同过滤的工具；
- 本次执行结果。

子代理不接收主代理完整对话历史，不读取或写入项目记忆，不获得编辑、命令执行、额外报告或工作流调度工具。

第一阶段不自动把依赖任务的完整消息注入下游上下文。主代理负责根据上游结果编写下游任务，避免隐式上下文膨胀。

## 数据流

```text
主代理调用 spawnSubagent(task, role, ...)
  -> 解析固定角色模板
  -> 角色工具白名单与父运行只读工具取交集
  -> 创建独立 ReactAgentRunner 和消息上下文
  -> 执行任务
  -> 将状态、事件和最终结果返回主代理
```

## 错误与资源控制

- 未知角色：创建失败，不生成子代理状态。
- 角色无可用工具：允许执行纯推理任务，但结果必须说明缺少工具证据。
- 超时、取消、依赖失败和并发限制：继续复用现有 `WorkflowOrchestrator` 行为。
- 主运行结束：取消所有未完成子代理并释放其上下文。

## 预计修改范围

- `src/extension/agent/workflow/types.ts`：增加角色 ID 和创建参数。
- 新增一个小型角色注册表，保存三个固定模板。
- `src/extension/agent/workflowOrchestrator.ts`：解析角色并保存到子代理上下文。
- `src/extension/model/providerRegistry.ts`：使用角色 prompt 创建 child runner。
- 更新对应单元测试和运行器级端到端测试。

不修改通用 `AgentRunner` 协议，不新增依赖，不增加持久化层或角色管理 UI。

## 验收标准

- 每个子代理快照都包含已解析的固定角色。
- 不传 `role` 时使用 `explorer`，现有创建调用保持兼容。
- 三个角色使用各自固定 system prompt。
- 角色与父运行权限取交集，任何角色都不能获得写入、命令或递归调度权限。
- 子代理仍保持独立消息历史和项目记忆隔离。
- 未知角色、工具越权和父运行取消都有回归测试。
- 受影响测试、全量测试、类型检查、编译和 `git diff --check` 通过。

## 非目标

- 常驻角色实例或跨任务角色记忆。
- 子代理之间直接通信。
- 由模型动态创建角色、提示词或工具权限。
- 为不同角色动态选择模型。
- 角色配置 UI、插件市场或远程角色注册。
