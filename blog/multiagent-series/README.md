# 多智能体是怎么跑起来的 · 系列索引

一个 AI Agent 能自己派出另一批 Agent 干活,这件事听起来很科幻。但拆开看,它既不需要新的模型能力,也不需要另一套运行时——**只需要三个普通的工具函数**。

这个系列用 [LoopAgent](https://github.com/oi12344/loopagent-vscode) 的真实实现,把"多智能体协调"从概念拆到代码:任务图怎么长出来、谁决定谁先跑、子智能体凭什么不越权、怎么判断一个 Agent 是卡住了还是在干活、两个 Agent 同时改同一个仓库怎么不打架。

## 目录

| # | 标题 | 讲什么 |
|---|------|--------|
| **01** | 一个 Agent 不够用的那一刻 | 单智能体在长任务里为什么会"失忆",上下文污染、能力过载、无法并行三个真问题 |
| **02** | 三个工具,就是全部编排 | `spawnSubagent` / `waitForSubagents` / `cancelSubagent`,以及任务图如何在运行时一个节点一个节点长出来 |
| **03** | 谁能跑,谁得等 | 调度器的一次心跳:就绪判定、并发上限、executor 串行化、五态迁移与失败级联取消 |
| **04** | 四个角色,四套权限 | explorer / reviewer / planner / executor,两段式工具收窄,以及子智能体的递归本质 |
| **05** | 它是卡住了,还是在干活? | 为什么墙钟超时一定误杀,四态推进判定、自适应观察窗,以及一堵没装上的兜底墙 |
| **06** | 让两个 executor 同时改代码 | 丢失更新为什么必然发生、git worktree 隔离、工具调用的路径重写、结算与验证检测 |

## 读之前

这个系列假设你已经知道 ReAct 循环是什么。如果没有,先看前一个系列 ReAct 是怎么跑起来的——本系列里的每个子智能体,都是那个循环的一个实例。

## 关于 LoopAgent

[LoopAgent](https://github.com/oi12344/loopagent-vscode) 是一个 VS Code AI 编程扩展,自带代码智能索引(SQLite FTS5 + 语义图)、函数调用式 ReAct 循环、多智能体编排。本系列引用的所有代码都在 `src/extension/agent/` 下,可以直接对着仓库读。
